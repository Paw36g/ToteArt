### DIRECTIVA QUIRÚRGICA: PARIDAD TOTAL VERCEL VS LIVE SERVER

**REGLA DE CONSERVACIÓN:**
- Prohibido tocar `styles.css`, la base de datos de Supabase, las alertas de checkout, la lógica de favoritos o los correos.
- No alterar el diseño visual de las tarjetas de pedidos ni los botones de entrega.
- Resolver estrictamente la sincronización asíncrona en producción para que Vercel se comporte exactamente igual que Live Server.

---

#### 1. SOLUCIÓN A PRODUCTOS VACÍOS EN VERCEL (`pedidos.html`)
**Causa:** En Vercel, por latencia de red, `pedidos.html` se renderiza antes de que la consulta asíncrona llene `window.PRODUCTS`. Como `PRODUCTS` está vacío en ese instante, el `.find()` no encuentra títulos ni fotos y deja el espacio en blanco.

**Acción en `pedidos.html`:**
1. Antes de invocar la función que dibuja las tarjetas, obligar a la página a esperar (`await`) que el catálogo de productos esté completamente cargado en memoria:
```javascript
async function asegurarCatalogoCargado() {
  if (Array.isArray(window.PRODUCTS) && window.PRODUCTS.length > 0) return;
  
  if (typeof loadProductsFromSupabase === 'function') {
    await loadProductsFromSupabase();
  } else if (typeof window.fetchProducts === 'function') {
    await window.fetchProducts();
  }
}

Asegurar que en el punto de entrada (DOMContentLoaded o inicio de script), se ejecute en este orden estricto:

document.addEventListener('DOMContentLoaded', async () => {
  await asegurarCatalogoCargado();
  await cargarVistaPedidos();
});

En el bucle de mapeo de productos de la tarjeta, agregar lectura defensiva directa de la orden por si la red fallara, asegurando que el título y la imagen siempre se muestren:

2. SOLUCIÓN AL CONTADOR EN CERO AL IR A PERFIL (perfil.html y app.js)
Causa: Al navegar a perfil.html, updateBadges() consulta únicamente el localStorage local (que en Vercel puede no tener la clave sincronizada) o no espera a Supabase, reseteando Mis Pedidos a (0).

Acción:
En app.js, dentro de la lógica que calcula el contador de ordersCountNav:

Si la sesión está activa (toteart_user), intentar leer de toteart_orders.

Si toteart_orders no tiene registros, consultar asíncronamente en Supabase la cantidad exacta de pedidos del usuario sin bloquear la página:

async function refrescarContadorPedidos() {
  const badge = document.getElementById('ordersCountNav');
  if (!badge) return;

  let session = {};
  try { session = JSON.parse(localStorage.getItem('toteart_user') || '{}'); } catch(e) {}
  const activeId = session.id_cliente || session.id_usuario;

  if (!activeId) {
    badge.textContent = '0';
    return;
  }

  // 1. Intentar desde caché local
  try {
    const local = JSON.parse(localStorage.getItem('toteart_orders') || '[]');
    const myOrders = local.filter(o => 
      (o.id_cliente === activeId || o.idCliente === activeId || (session.email && o.customerEmail === session.email))
    );
    if (myOrders.length > 0) {
      badge.textContent = myOrders.length;
      return;
    }
  } catch(e) {}

  // 2. Si no hay en local, consultar en Supabase
  if (window.supabaseClient) {
    try {
      const { count, error } = await window.supabaseClient
        .from('pedidos')
        .select('*', { count: 'exact', head: true })
        .eq('id_cliente', activeId);

      if (!error && count !== null) {
        badge.textContent = count;
      }
    } catch(err) {}
  }
}

Asegurar que updateBadges() en perfil.html invoque esta validación.
